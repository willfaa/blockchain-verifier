1. PERSIAPAN / CLEANUP MANDATORI (Penting jika ada konflik port/sertifikat)
-----------------------------------------------------------------------------
A. Matikan Service Docker bawaan WSL (agar tidak konflik port 7050 7051 7054 dengan Docker Desktop):
   sudo service docker stop
   sudo systemctl stop docker
   sudo systemctl stop docker.socket

B. Hapus container & volume usang / legacy:
   docker rm -f ca_orderer ca_org1 ca_org2 peer0.org1.example.com peer0.org2.example.com orderer.example.com
   docker volume prune -f

C. Bersihkan sisa sertifikat lama di folder network (WSL):
   cd ~/fabric-samples/test-network
   ./network.sh down
   # Hapus manual jika masih tersisa:
   rm -rf organizations/peerOrganizations
   rm -rf organizations/ordererOrganizations
   rm -rf organizations/fabric-ca/org1/{msp,*.pem,*.db,Issuer*}
   rm -rf organizations/fabric-ca/org2/{msp,*.pem,*.db,Issuer*}
   rm -rf organizations/fabric-ca/ordererOrg/{msp,*.pem,*.db,Issuer*}

-----------------------------------------------------------------------------

4. PENGUJIAN / VALIDASI VIA PEER CLI (Jalankan di WSL)
-----------------------------------------------------------------------------
A. Set Environment variables terlebih dahulu (Gunakan absolute path agar bisa dijalankan dari folder mana saja di WSL):
   export PATH=~/fabric-samples/bin:$PATH
   export FABRIC_CFG_PATH=~/fabric-samples/config/
   export CORE_PEER_TLS_ENABLED=true
   export CORE_PEER_LOCALMSPID="Org1MSP"
   export CORE_PEER_TLS_ROOTCERT_FILE=~/fabric-samples/test-network/organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/tls/ca.crt

   export CORE_PEER_ADDRESS=localhost:7051

B. Check list channel & chaincode terinstall:
   peer channel list
   peer lifecycle chaincode queryinstalled

C. Query data awal (pastikan CORE_PEER di atas sudah di-export):
   peer chaincode query -C chainnesa -n basic -c '{"function":"GetAllCertificates","Args":[]}'

6. PENANGANAN MASALAH PORT & CONTAINER CRASH / PAUSED / STOPPED
-----------------------------------------------------------------------------

A. Port 8081 Terpakai (Konflik IPFS vs Apache httpd.exe)
   - Masalah: IPFS error bind port 8081 karena dipakai `httpd.exe` (Apache) bawaan system.
   - Solusi: IPFS Gateway dipindahkan ke port 8082.
     1. Ubah file konfigurasi IPFS di Windows (C:\Users\willfaa\.ipfs\config) pada bagian Gateway:
        "Gateway": "/ip4/127.0.0.1/tcp/8082"
     2. Edit file .env di backend:
        IPFS_GATEWAY=http://127.0.0.1:8082
     3. Jalankan ulang daemon IPFS.

B. Container Docker Terjeda (Paused)
   - Gejala: Transaksi blockchain gantung (timeout) dan console dashboard menunjukkan offline.
   - Solusi (Jalankan di WSL atau CMD):
     docker unpause $(docker ps -aq -f status=paused)

C. Container Docker Mati (Exited / Stopped)
   - Gejala: Error saat backend melakukan query ke channel/peer.
   - Solusi: Nyalakan ulang semua container yang mati tanpa restart network total:
     docker start $(docker ps -aq -f status=exited)
   - Jika masih gagal, lakukan down-up bersih:
      cd ~/fabric-samples/test-network && ./network.sh down && ./network.sh up createChannel -c chainnesa -ca

D. Daemon Docker Tidak Terdeteksi di WSL
   - Gejala: `Cannot connect to the Docker daemon...`
   - Solusi:
     1. Pastikan Docker Desktop di Windows sudah berjalan.
     2. Jika hang/macet, jalankan perintah reset di Windows PowerShell:
        wsl --shutdown
     3. Buka kembali Docker Desktop dan terminal WSL Anda.

E. Pembersihan Port Terkunci (Windows PowerShell Admin)
   - Cek PID yang memakai port backend (4000) atau HLF (7051):
     netstat -ano | findstr :4000
   - Matikan proses paksa:
     taskkill /PID <PID_PROSES> /F

8. MANAJEMEN CONTAINER DOCKER & TUNNELING
-----------------------------------------------------------------------------
Metode 1: Stop & Start (Paling Direkomendasikan)
Metode ini akan mematikan container secara aman (langkah graceful shutdown). RAM dan CPU akan dibebaskan sepenuhnya, dan data ledger Anda tetap aman di dalam Docker Volume. Ini adalah pilihan terbaik jika Anda ingin mematikan komputer/WSL dan melanjutkan pekerjaan besok.
cd ~/fabric-samples/test-network
docker stop $(docker ps -aq)
docker start $(docker ps -aq)

Metode 2: Pause & Unpause (Freeze Proses)
Metode ini menggunakan fitur cgroups Linux untuk membekukan (freeze) proses container. Container tidak dimatikan, melainkan hanya dihentikan eksekusinya. CPU tidak akan digunakan, tetapi RAM tetap teralokasi.
cd ~/fabric-samples/test-network
docker pause $(docker ps -q)
docker unpause $(docker ps -q)
